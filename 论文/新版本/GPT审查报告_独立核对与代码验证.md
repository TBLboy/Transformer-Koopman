## 1. 对 GPT 新增技术发现的独立验证

### 1.1 T1｜首式与"非 Markov 完备"冲突

- **正文**：L167–172 先给出 `x_{k+1}=F(x_k,u_k)`、`x_k` 为 measured state，同段末又写 `Here x_k denotes the measured coordinates used by the predictor; finite history is introduced below when these coordinates are not Markov-complete.`；§III-B L227 再次强化 `the measured state need not form a complete Markov state`。
- **我的复核**：无需外部资料，纯文本逻辑。`x_{k+1}=F(x_k,u_k)` 是确定性一阶映射，等价于断言 `x_k` 是完备状态；同一节又断言它不必完备 → 自相矛盾。**✅ 成立**。
- **补充**：论文 §V-C（L570）已明确"不假定存在确定性参考映射"，即作者在理论章已经意识到这一点；矛盾只出现在 §III 的建模背景处，因此**修法应低成本**：要么引入隐状态 `s_k`/`x_k=h(s_k)`，要么把首式明示为"理想完备状态的教科书背景，不是对本文测量信号的假设"。后者改动更小、不影响 §V 的任何推导。
- **与 GPT 的差异**：GPT 标 **【必须】**；我同意性质，但强调这是**表述层一致性**问题，不是数学错误，改动量约 1–2 句。

### 1.2 T2｜`A` 与受控 Koopman 算子 `K_u` 的关系

- **正文**：L174–178 定义 `(K_u φ)(x)=φ(F(x,u))`（对固定 `u` 的一族算子）；L186–190 EDMD 有限维提升；L191 首现 `z_{k+1} ≈ A z_k + B u_k`，无维度、无角色。
- **我的复核**：固定 `u` 时 `K_u` 是一族算子，而 `z_{k+1}≈Az_k+Bu_k` 是把输入显式拉成仿射项的**额外建模选择**。两者不能等同；经典 EDMD 也不会自动给出 `B`。GPT 的反对**正确**，我的上轮建议**错误**（见 §2.1）。
- **正确表述**：`(A,B)` 是 controlled observable evolution 的有限维输入仿射代理（surrogate），`A` 为标称提升转移、`B` 为输入映射。**✅ 成立**。

### 1.3 T3｜Stage 0 只监督物理输出行（关键发现）

- **正文**：L370–378 `L_init = Σ‖C(A_0 z_k + B u_k) − x_{k+1}‖²`，`C=[I_n 0]`。
- **我的复核（代数）**：令 `Y=A_0z+Bu`，残差 `r=CY−x_{k+1}∈R^n`；对 `A_0` 的梯度为 `z·(Cᵀr)ᵀ`，而 `Cᵀr` 仅在**前 n 个分量非零**。故 `∂L_init/∂A_0[j,:]=0`、`∂L_init/∂B[j,:]=0`（`j=n+1..d`）。`θ` 仍可经前 n 行反传。**✅ 成立**。
- **我的复核（代码）**：产出 Stage 0 权重的实现是 `gate_context_koopman.py` 的 `CtxKoopman(mode="fixed")`，其训练损失为 `F.mse_loss(model(XH,UH,UT), XN)`（L92），而 `forward` 返回 `decoder(z_next)=z_next[:, :n]=Cz_next`（L74–77）。
  → **实现确实是"物理一步损失"**，与论文公式一致，因此上述"隐藏行无数据梯度"对该 artifact 真实成立（隐藏行停留在初始化：`A_0=I+0.01·randn`、`B=0.1·randn`；Stage 1 才由 rollout 梯度训练）。
- **连带（GPT 未点明的两处措辞）**：
  - L380 `well-scaled lifted representation and a data-fitted nominal base operator` → 对"仅物理输出被监督"这一事实偏强，应改为"one-step physical-prediction-based initialization"。
  - L380 `it is the only stage optimized exclusively on the encoder-consistent one-step latent distribution` 这一句**本身是准确的**（指训练样本分布，不是损失空间），不需要改；不要与上一条一起删。

### 1.4 T4｜`w_k` 与 `δ°_k` 的精确关系（我独立复算）

- **定义**：§IV-C L456 `w_k = z^E_{k+1} − (A(c_k) z^E_k + B u_k)`；§V-C L567–573 `δ°_k=‖ξ°_{k+1}−F_Θ(ξ°_k,u_k)‖₂`。
- **我的推导**：`ξ°_k=col(x_{k-P+1:k}, u_{k-P+1:k-1}, g_θ(X_k))`。比较 `ξ°_{k+1}` 与 `F_Θ(ξ°_k,u_k)`：
  1. 历史区组：`F_Θ` 追加的是解码反馈 `C(A(c_k)z^E_k+Bu_k)`；由 `w_k` 的定义它等于 `x_{k+1} − Cw_k`。故差值 = `+Cw_k`；
  2. 输入区组：两者移位相同（都用 `u_{k+1-P:k}`），差值 = `0`；
  3. 潜变量区组：`g_θ(X_{k+1}) − (A(c_k)z^E_k+Bu_k) = w_k`。
  → `ξ°_{k+1}−F_Θ(ξ°_k,u_k)=col(0,…,0,Cw_k,0,…,0,w_k)`，故 **`(δ°_k)²=‖Cw_k‖²+‖w_k‖²`，且 `‖w_k‖≤δ°_k≤√2‖w_k‖`**。**✅ 成立，与 GPT 完全一致。**
- **边界**：该恒等式依赖 ①历史移位约定 ②`C=[I_n 0]` ③记录历史上"下一时刻重新编码"的定义 ④内部解码反馈；不适用于一般反馈结构。GPT 已列出这些条件 ✓。
- **含义**：`w_k` 不是第三个独立误差量，而是 `δ°_k` 的组成部分 → 支持"删 §IV-C 独立小节、在新 §V-B 一次性定义二者关系"的处理。同时 Assumption 1 的 `δ°_k≤ε` 自动给出 `‖w_k‖≤ε`。

### 1.5 T5｜二阶 Taylor 余项在 ReLU 分段边界上的条件不足

- **正文**：L598–600（Assumption 3）允许扰动线段穿越有限个光滑区域，L661–685 据此使用二阶积分余项。
- **我的复核（用 GPT 的反例逐步验算）**：`f(t)=ReLU(t)`，名义点 `t̄=−a`，扰动 `δt=2a`。
  - `f(−a)=0`，`f'(−a)=0` → 线性预测 = `0`；实际终点 `f(a)=a` → 余项 `R=a`。
  - 两个光滑区域内 `f''=0` → 按现有假设取 `M_F=0` → 界给出 `R≤0`。**矛盾。✅ 成立。**
- **原因**：二阶积分余项要求 `F_Θ` 在整条线段上 `C²`；一阶导数在激活切换处跳变时，该形式不成立（无论分段内二阶导多小）。
- **修法**：把条件收紧为"名义点与被扰动线段位于**同一**局部光滑区域（该区域内二阶导有界）"；若要跨边界，需另行引入并证明一阶导的 Lipschitz 条件。**若只改小节位置而不改条件，等于保留一个错误的通用保证**（GPT 的警告正确）。

### 1.6 T6｜低秩有界 ⇒ well-conditioned？

- **正文**：L397 `... so ‖A(c)−A_0‖₂ is bounded uniformly in c.` 前置句为 `so that the lifted dynamics remain well-conditioned`。
- **我的复核（界）**：`‖U diag(γ) Vᵀ‖₂ ≤ ‖U‖₂‖γ‖_∞‖V‖₂ ≤ √r·g_max·√r = r·g_max`（单位列范数下 `‖U‖_F=√r`，`‖U‖₂≤√r`）。**✅ 界成立**。
- **我的复核（推断）**：该界只约束"修正幅值"，不推出可逆性、条件数、`‖A(c)‖₂<1`、`ρ(A(c))<1`、乘积一致收缩或闭环稳定。**✅ GPT 的反对成立**，`well-conditioned` 应删或改为 `bounded correction magnitude`。
- **代码旁证**：`gate14_stabilize.py` L44 注释声称 `‖dA‖₂≤delta_A`；按上述推导安全界应为 `r·δ_A`（r=2、δ_A=0.07 → ≤0.14）。**代码注释偏乐观**，属工程注释问题，但**论文若要写具体常数，应写 `r·g_max`**（见 §4-N4）。

### 1.7 T7｜§V-B 证明符号笔误

- **正文**：L536–541：递归写作 `e_{k+1}=A(c_k)e_k + r_k`，下一行却定义 `r^z_k = A(c_k)z^E_k + Bu_k − z^E_{k+1}`；L542 又用 `‖r^z_k‖₂=ε_k`。
- **复核**：`r_k` 与 `r^z_k` 指同一量，符号不统一。**✅ 成立**（我上一轮清单漏了这条）。属局部笔误，改动 1 处。

### 1.8 R2｜内部 rollout 下 `C(z^P−z^E)=0`

- **复核**：`z^E_{k+i}=g_θ(X̂_{k+i})=[x̂_{k+i};h_θ(X̂_{k+i})]`，而 `X̂` 的最新一行就是解码反馈 `C z^P_{k+i}`（§V-A 证明 L490 与 §VI-A eq. `scheduled_predictor` 都如此定义）。由状态保持性 `C g_θ(·)=最新状态`，故 `C(z^P_{k+i}−z^E_{k+i})=0`。**✅ 成立**。
- **含义与边界**：`d_k` 度量的是 `d−n` 维隐藏坐标的路径不一致，不是同刻物理误差；这不削弱 Prop 2（隐藏不一致会经 `A(c)` 影响后续物理解码），但**正文应显式区分**，否则容易被审稿人误读为"论文用 latent 量冒充物理误差"。
- **附带澄清（建议一并写入）**：诊断中计算 `z^E` 需要在**预测历史**上离线再跑一次编码器，这与 RTI-SP"在线不重编码"不矛盾；正文最好点明这一区别，避免"never re-encodes"被质疑自相矛盾。
- **代码旁证**：`gate14_stabilize.py` 的 `openloop_forward`（L76–84）与 `eval_prop(sched=True)`（L133–147）确实只在起点 `model.encoder(xh0)`，随后 `A,B = model.get_AB(xh, uh)` 用**解码历史**重算 context、`z` 只做线性传播 ✓，与 §V-A/§VI-A 的定义完全一致。

### 1.9 T8 / T9｜措辞强度

- **T8**：§V-B 严格给出的是 `z^P` 与 `g_θ(X̂)` 两条路径差的时间递推，论文措辞 `precisely the distribution shift analyzed in Section V-B`（L395）把它说成已证明的"分布漂移"。**✅ 应改为** `rollout mismatch between encoder-initialized and recursively propagated latent states`。

## 4. 代码核对带来的新发现（两份报告都没有）

### N1｜论文描述的模型不在迁移仓库 `训练代码/` 里【复现性】
- `训练代码/` 的 `src/patchtst_koopman/models/koopman_dynamics.py` 与部署资产 `deploy/algorithms/tk_assets/transformer_koopman_model.py` 都是**单一固定矩阵 `A`（d×d）+ `B`**，**没有 context 网络、没有低秩 `A(c)`、没有 `r`**。
- 论文的模型（context MLP + `A_0+U diag(γ) Vᵀ` + 预算/归一化）**只实现在 `杂项/研究代码/`**（`gate_context_koopman.py`、`gate14_stabilize.py`）。
- 仓库内已有同样结论的记录：`杂项/流程脚本/record_r4.py` L69–70、`record_audit.py` L31。
- **对论文的影响**：这是**复现路径**问题而非论文文字错误（论文不必交代代码仓库结构）；但它意味着 TASK-007（P=8 重训）与后续"论文↔代码对齐"必须明确以 `杂项/研究代码` 的实现为准，不要把 `训练代码/` 当作论文模型实现。

### N2｜RTI-RE 与 RTI-SP 的对比用的是**两个不同的模型实例**【实验口径】
- `gate14d_rti.py` L92–93：RTI-RE 加载 `CtxKoopman(CFG,"A",r=2)` ← `A_r2.pt`（**未加预算约束**的 A-调制路线）；RTI-SP 加载 `BudgetedCtxKoopman` ← `A_stab_openloop_lam0.0_rho0.99.pt`（**预算化 + 开环训练**）。
- 因此 Table I 中 "RTI-SP vs RTI-RE" 的 RMSE 比较**不是同一预测器的两种预测机制对比**，而是两条模型路线 + 两种机制混在一起；"快 2.3×/2.1×"由机制决定（可归因），但精度差异不可单独归因于重编码机制。
- **处理**：属实验章口径问题（本轮 §VII 搁置）。**建议在实验章明确写出两个控制器各自加载的模型**，或补一个"同一模型、两种机制"的对照，以免审稿人质疑公平性。

### N3｜部署 checkpoint 与论文模型不同【已知，确认】
部署资产实现的是**固定 A 的旧路线**，与论文的 `A(c)` 模型不一致；与 DEC-028（"部署 ckpt ≠ current config，P2 真机前必须重训"）一致。本轮仅登记，不进入论文文字。

### N4｜低秩界的安全常量
`gate14_stabilize.py` L44 的注释声称 `‖dA‖₂ ≤ delta_A`。在仅"逐列单位范数"（非正交）下，安全界为 `‖U‖₂·max|a_i|·‖V‖₂ ≤ √r·δ_A·√r = r·δ_A`（r=2 → ≤0.14）。**论文若给出具体常数，应写 `r·g_max`**；若只写"有界"，则完全安全。属代码注释与论文共同需要注意的精度问题，非缺陷。
