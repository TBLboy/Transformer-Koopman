## 2. 采样周期与时间轴

| 项 | 数值 |
|---|---|
| 每条记录样本数 | **300**（100 条全部相同） |
| 名义采样周期 | **0.2 s（5 Hz）** |
| dt 全局范围 | min `0.199933129` / max `0.200197689` / mean `0.200008607` / std `5.73e-05` |
| 记录内 dt 波动 | **0**（29900 个 dt 中 0 个偏离该记录均值 >1e-9） |
| 每条记录时间跨度 | 59.78 s – 59.859 s（≈60 s） |
| 重复时间戳 | 0 |
| 时间倒序 | 0 条记录 |
| 记录起始时刻 | 全部 `t[0] = 0.0`（处理后按记录重新归零，为 no-op） |

**重要事实**：每条记录内部的 dt 是**严格常数**，但不同记录之间的常数略有差异（0.19993–0.20020 s，±0.07%）。
这意味着时间轴是**按索引重建的均匀采样**，不是原始墙钟时间戳（真实日志的墙钟时间戳会呈现抖动）。
→ 对本实验的影响：dt 可安全视为常数 0.2 s；但**不能**用数据反推真实采样抖动。

## 4. 数据划分

`scripts/prepare_data.py:37-47` 声明：按**文件名字符串序**排序，再按固定条数切 70/20/10。

```
字符串序: 01..09, 10, 100, 11, 12, ... 99      ← "100" 排在 "10" 之后、"11" 之前
train = 位置 1..70   → 01..09, 10, 100, 11..69
val   = 位置 71..90  → 70..89
test  = 位置 91..100 → 90..99
```

**独立复核（`audit_data.py` §B）**：按上述规则从原始 npz 重建，与 `处理后的数据/*.npz` 的
`x / u / t / trajectory_id` 四数组**逐元素完全相等**（`reproduces_from_raw` 全为 `true`）。
→ 划分可复现，且不依赖随机种子。

**协议符合性评估**（对照计划书 §2.1）：

- ✅ 按**整条记录**划分（不跨轨迹随机切窗口），无重叠窗口泄漏。
- ✅ 预处理参数可在 train 上拟合后冻结（§7 已给出 train-only 常数）。
- ⚠️ 划分是**文件名序**，不是按工况/难度分层。计划书 §2.1.4 要求的「未见工况泛化」**数据不支持**：
  100 条记录是同平台同任务的重复实验，未标注工况标签 → **不得声称跨工况泛化**。
- ⚠️ 若将来需要「同工况未来时间段」评估，需按记录内时间先后另切，且不得跨记录边界。

## 6. 数据来源判定（真实执行器日志 / 仿真 / 混合）

**结论：真实平台采集（用户 2026-10-11 确认）。**

- 用户确认：「平台状态 xy 表示光点在二维屏幕上的移动坐标，u 就是电机控制量，数据来源于真实平台采集」。
- 数据侧旁证（与用户确认一致）：状态轨迹连续平滑、无饱和平台、`u` 为连续浮点、与 experiment3 真实平台跟踪实验使用同一 `u_limit`/坐标系语义。
- 与 `软控逻辑.txt` 的对应：`x` 侧为视觉反馈（光点质心坐标，`:377`），`u_k=(N_h,N_v)` 为电机「移动单位」（`:224,227`），采样周期默认 0.2 s（`:214`）。
- **保留的技术说明（不改变来源结论）**：每条记录内 dt 严格为常数（0/29900 偏离），说明时间轴是按索引重建的均匀采样，而非原始墙钟时间戳；记录间 dt 常数略有差异（0.19993–0.20020 s）。因此不得用本数据推断真实采样抖动。

**对实验的约束**：可使用「真实平台数据」措辞；但 WP-C 的闭环结论仍须严格区分**离线预测回放 / 闭环仿真 / 真实硬件闭环**（计划书 §6），不得把离线回放表述为闭环控制，也不得用被测试控制器自身的模型当唯一 plant 来声称控制有效。
